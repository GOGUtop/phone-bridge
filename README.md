# Anima 小手机桥

面向 SillyTavern 的虚构 iPhone 风格小手机，并与 Anima Memory System 双向同步。当前版本 0.5.0。完整手机记录保存在聊天元数据及扩展备份中，近期状态写入 `anima_data.手机` 和 `anima_data.幕后状态`；历史记录另行写入并检索 Anima 向量库。

## 0.5.0 修复与界面更新

- 修复 HTTP 等环境不提供 `crypto.randomUUID` 时记忆写入失败的问题；仍需正常运行的 Anima 后端才能完成向量写入。
- 现场人物不再接受未经确认的空结果；支持中文字段和按姓名组织的对象，读取本轮完整正文，避免长正文尾部被截掉。同楼层可重新提取现场，不重复扣钱或发消息。失败保留上一份有效状态，并显示重试入口。
- 幕后栏目切换保留横向滑条位置和记忆详情展开状态。
- 人物整理读取角色卡、绑定/全局/聊天世界书及正文中的具名人物；模型必须提供原文证据。别名合并保留旧对话与红包归属，不因下一轮漏提取删除原联系人；故事标题不直接作为一个人。按有证据的关系整理微信群。
- 微信恢复四栏导航、通讯录、群聊和朋友圈；朋友圈支持发布、点赞、评论。各应用有独立的列表、查询、订单或账户页面。支付宝转账只记支付宝账户，不串到微信会话。
- 购物加入商品详情、购物车和结算；外卖加入店铺菜单和分应用订单；出行加入行程查询；音乐可添加歌曲和分享至微信。
- 界面参考要求限定 2024–2026 年，来源及尚未核实的截图日期见 [REFERENCE-SOURCES.md](REFERENCE-SOURCES.md)。这是可交互的模拟界面，不是官方 APP 的逐像素复制，也没有接入真实支付、地图或电商账户。

更新时整体替换扩展文件，不能只换 `index.js`，新增的模块、样式与 `assets` 都要上传。旧聊天元数据自动沿用，不必清空聊天，也不必重导正文预设。本次服务端接口未变，已安装并能运行的 0.4.0 服务端可继续用。界面测试使用模拟 API；真实模型的提取质量仍取决于模型及输出长度配置。

## 0.4.0 新增

- 短信、文字电话、好友申请、按世界观建立群聊，私聊和群聊统一按最新消息排序。
- 世界书具名人物及原文证据提取、人物别名合并，不把触发关键词直接当联系人。陌生人需要先接受申请。
- 当前微信会话内发红包/转账、领取状态、群红包份额；支付宝、银行独立账本。支付均为模拟。
- 淘宝、京东、打车、航班、酒店的模型生成目录、选单支付、商家/司机对话和统一订单中心。正文明确发生的订单也可同步。
- 保留约定与待办、秘密与伏笔、幕后人物、世界事件；增加朋友圈、心灵声音、私人日记、衣橱、纪念日、知情账本及经剧情授权展示的 NPC 手机。
- 每层正文完成后生成增量世界事件，后台连续失败三次出现重试/跳过窗口，不修改正文。
- 手机对话检索参与者有权知道的旧记录；正文生成前检索 Anima 历史并注入。支持本地检索降级和手动重试。
- 音乐歌单可添加音频直链并播放；没有音源的歌曲只记录剧情选曲，不输出音频。不提供网易云登录或付费曲库访问。
- 手机按钮与幕后条均可自由拖动并记住位置，点击和消息有轻量动效。
- AI 接力拆分为独立扩展，本扩展不包含“问作者”。

## 功能

- 微信私聊、微信群和朋友圈，可直接与世界中的 NPC 互动。
- 微信支付、支付宝、银行卡、私聊红包、群红包和工资到账。
- 饿了么、美团外卖、大众点评和网易云音乐。
- 发送 API 专门处理手机互动；实时更新 API 在每层正文完成后校准手机和幕后状态。
- 实时更新 API 故障时自动改用发送 API，冷却后自动检测并切回。
- 校准模型返回损坏 JSON 时自动修复一次；仍无效则把它视为更新 API 故障并切换发送 API。
- 订单按剧情时间和正文事实推进，不按现实时间倒计时。
- 从当前角色绑定的世界书及正文校准结果中导入具名 NPC 联系人。
- 可自由拖动且记忆位置的手机悬浮按钮。
- 独立的幕后状态条，包含现场与幕后生活的多个栏目，并显示记忆写入和检索状态。
- 默认自动适配新角色卡：等待 Anima 建立默认提示词后，仅追加一次桥接规则，不覆盖卡内原规则。
- 每个聊天存档独立保存；重复校准不会重复发消息、记账或推进订单。

所有支付、银行、订单和商家均为角色扮演世界中的模拟数据，不连接真实商业服务。

## GitHub 安装

在 SillyTavern 扩展管理器中选择“安装扩展”，粘贴：

```text
https://github.com/GOGUtop/phone-bridge
```

也可在 SillyTavern 目录执行：

```sh
git clone https://github.com/GOGUtop/phone-bridge public/scripts/extensions/third-party/anima-phone-bridge
```

## 安装服务端插件

进入扩展目录后执行：

```sh
sh install-server.sh /home/www/SillyTavern2
```

确认 SillyTavern 的 `config.yaml` 已开启：

```yaml
enableServerPlugins: true
```

然后完整重启 SillyTavern。API Key 只保存在 `data/default-user/anima-phone-bridge/config.json`，不会由设置接口回传到浏览器。

## 双 API 设置

打开小手机的“设置”：

1. “发送 API”填写 API 地址、API Key 和模型，用于微信、群聊、朋友圈及应用互动。
2. “实时更新 API”用于正文完成后的状态校准。整组留空时会共用发送 API。
3. 两组 API 均可单独拉取模型和测试连接。
4. 更新 API 失败后，会在设定的恢复间隔内使用发送 API；间隔结束后的下一次正文校准会自动尝试恢复。

接口需兼容 OpenAI Chat Completions 与 `/models`。部分中转站不开放模型列表时，可直接手动填写模型名称。

这里的“实时更新”指正文生成完成、切换聊天或打开手机后的事件驱动校准，不是每秒轮询。它因此以剧情时间为准，也避免无意义消耗 API。

## Anima 适配

1. 保持 Anima 的状态变量和世界书注入开启。
2. 在手机设置中保持“自动适配新角色卡”开启，旧卡点击“立即适配”。插件会更新自己的规则，无需每张卡重新导入文件。
3. 导入配套“落魄的作家-小手机桥-v0.4.json”即可，已含正文桥接规则；其他预设才需要手动加入 `presets/main-preset-addon.txt`。
4. Anima 已注入完整状态时，不要再重复添加状态宏。

`v0.3.1` 起不再需要为每张新角色卡手动导入状态提示词。“设置 → 自动适配新角色卡”默认开启；也可点击“立即适配”检查当前卡。角色卡中已有的提示词会完整保留，插件只维护标题为“📱Anima 小手机桥｜状态维护补充规则”的单独条目。`v0.3.3` 起，点击适配后会同步刷新当前打开的 Anima 提示词列表。`v0.3.4` 起，桥接规则会自动排在 Anima 的“状态更新提示词”和最终“强调”之前；旧版本放在末尾的规则会在再次适配时自动移到正确位置。

桥接依赖酒馆助手提供 `TavernHelper` 变量接口。尚无 AI 正文楼层时，手机仍可使用，但会等待首条正文出现后再写入 Anima。

## 数据与记忆边界

- 完整消息、朋友圈、账本、订单和幕后历史保存在当前聊天元数据，扩展设置保留兼容备份；近期展示窗口不等于删除历史。
- 状态变量保存近期摘要；完整历史另通过 Anima 的 `/insert` 写入当前聊天专用集合 `apb_<chat scope>`。必须配置好 Anima 的向量 API 和服务端，写入成功才显示已写入条数。
- 正文生成前调用 Anima `/query` 召回该集合，并注入有效记录；向量服务不可用时使用本地相关性检索。手机内 NPC 回复也检索其有权知道的本地历史。
- 私人信息逐条标明知情者。作者层可用来保持连续性，不代表场内所有 NPC 都知道。模型仍可能误读，不能承诺绝不遗忘或绝不越过知情边界。
- 在幕后状态的“记忆同步”中查看结果并重试。仅看到状态栏变化，不代表向量写入已成功。
- 本地测试使用模拟 Anima 接口验证链路。真实模型生成质量、实际向量服务及你的酒馆版本，需安装后联调。
- 切换聊天会隔离新的请求写入；不提供删除楼层或 swipe 后自动回滚整套资金与世界历史的功能，试用前备份聊天，不要把重写旧楼层当成撤销支付。

## 使用限制

本插件是故事模拟器，不连接真实微信、支付、购物、短信或电话服务。电话是文字对话，不是语音通话。默认余额和旧版餐厅/曲目均为虚构初始数据；正文明确的收入消费会持续记账。

实时更新 API 建议最大输出至少 4096；人物很多时可提高至 8192。NPC 自主性逐轮评估，允许零条或多条消息，不强制每轮刷屏。

API 配置沿用 `data/default-user` 单用户存储，不适合把本服务直接开放给互不信任的多个酒馆用户。不要上传 `data` 目录或 API Key 到 GitHub。
